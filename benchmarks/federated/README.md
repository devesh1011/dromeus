# Local classification data and non-IID experiments

This package exercises Dromeus with independently held local datasets. Its synthetic
CPU experiments are separate from the frozen M2 CIFAR-10/GPU benchmarks in
[`benchmarks/results/m2`](../results/m2/README.md). Manifest v3 and the accepted M2
experiment identities remain unchanged.

The [2026-09-07 real-local-AXL report](../results/local-data-validation/20260907-axl/report.md)
retains the completed five-profile experiment, configuration, provenance, logs,
and results. Every predeclared gate passed, and all identity/reference trajectories
matched exactly. These are synthetic CPU development results, not official M2
GPU/WAN or NCCL acceptance evidence.

## Shared task and private data

[Manifest v4](../../src/dromeus/manifests/models.py) declares a common classification
task, ordered label meanings, preprocessing identity, model, training policy, and
fixed even membership from 4 through 16. Each node supplies its own records and may
have different dataset sizes, label proportions, or missing classes.

The objective is **equal-node**: nodes perform the same declared number of local
steps and contribute equally to the pair update. Dataset size does not weight the
update. Tiny datasets cycle through their local loader as needed.

The following is a **fragment** of a complete shared draft for a custom linear
classifier; algorithm, optimizer, environment, transport, and remaining policy
fields are also required. Both hashes shown correspond to the definitions in the
Python example below. Host v4 runs may omit `container_image_digest`.

```yaml
manifest_version: 4
expected_participant_count: 4
model_id: custom-linear-v1
model_definition_hash: cd2b520fac3661744120d0d7cfe1752a72a2330264281e4b0f3bbe571c4e5eb4
dataset:
  dataset_id: local-classification-v1
  input_shape: [8]
  input_dtype: float32
  label_names: [class-0, class-1, class-2, class-3]
  preprocessing_hash: 02b62d6127486d6a085e355680d15f4edd87a263764dd3104b0c7a02cc489298
  objective: equal-node
# Within the complete training policy:
# crop_padding: 0
# normalize: false
```

Label `0` means `class-0` on every node. The shared manifest contains no local data
paths, record fingerprints, or sample counts.

[Local data validation](../../src/dromeus/adapters/classification/data.py) accepts deterministic,
sized PyTorch datasets whose items are `(inputs, target)` pairs. Inputs must already
be preprocessed, finite FP32 tensors or NumPy arrays matching `input_shape`; targets
must be scalar integral class indices within the shared label range. Preflight
reads every record and checks repeatability. The returned dataset wrappers continue
checking schema, length, content, and order during access. Random dataset transforms
are unsupported by this deterministic interface.

Evaluation is explicitly optional. Provide separately held-out data, or declare its
absence; the local trainer returns `None` when it has none. It never evaluates its
training set as a fallback. Validation rejects overlapping source indices in views
of the same PyTorch dataset, including nested `Subset` views, and identical complete
training/evaluation collections. Matching individual observations in independently
owned datasets do not establish shared record identity. Callers must designate
disjoint held-out records for arbitrary custom datasets; validation does not certify
statistical independence.

## Private JSON/NPZ binding

Each node can load a private JSON binding such as:

```json
{
  "schema_version": 1,
  "source_id": "node-0-dataset-v1",
  "label_names": ["class-0", "class-1", "class-2", "class-3"],
  "preprocessing_hash": "02b62d6127486d6a085e355680d15f4edd87a263764dd3104b0c7a02cc489298",
  "train_path": "train.npz",
  "evaluation_path": "evaluation.npz"
}
```

Set `evaluation_path` to `null` when no held-out set exists. Paths must resolve to
files inside the binding directory. NPZ files contain exactly `inputs` with dtype
`float32` and shape `[N, *input_shape]`, and `labels` with dtype `int64` and shape
`[N]`, with `N > 0`. Loading disables pickle. Identical training/evaluation sets and
unknown binding fields are rejected.

Keep bindings and real private datasets outside the shared submission. The synthetic
datasets generated by this benchmark are intended to be retained as reproducible
experiment inputs.

## Run a custom model

Pass a local factory to [`dromeus.node.run_node`](../../src/dromeus/node.py). The
factory returns the **runtime** preparer; the lower-level training preparer serves
direct trainer integrations.

```python
import asyncio
from pathlib import Path

import torch
from torch import nn

from dromeus.node import load_node_config, run_node
from dromeus.adapters.classification.runtime import prepare_local_training
from dromeus.adapters.classification.data import load_local_data

MODEL_DEFINITION = "torch.nn.Linear(in_features=8,out_features=4,bias=True);float32"
# preprocessing_hash = SHA256("identity-fp32-v1") for these prepared inputs.

def local_training(draft):
    torch.manual_seed(17)
    return prepare_local_training(
        draft=draft,
        data=load_local_data(Path("private/data.json")),
        model=nn.Linear(8, 4),
        model_definition=MODEL_DEFINITION,
        seed=17,
        device="cpu",
    )

config = load_node_config(Path("node.yaml"))
asyncio.run(run_node(config, prepare_training=local_training))
```

The node configuration supplies only its role, draft, local AXL bridge, invitation,
and run directory. All data/model choices belong to the local factory; the earlier
`local_data_path` shortcut and automatic model registry selection have been removed.
The initiator distributes shared initial weights and every node checks its tensor
schema before READY.

The example above explicitly opts into the classification adapter. For a custom
loss, optimizer, or regression task, use the [application-owned training interface](../../examples/README.md).
The runtime does not require a classification model, labels, or accuracy metrics.

[Local training](../../src/dromeus/adapters/classification/trainer.py) deep-copies the supplied model,
validates its definition hash and output shape, and supports CPU or CUDA. Durable
checkpoints include the local data fingerprint, optimizer/loader state, and private
Torch CPU/CUDA RNG state. A versioned restore context also binds model identity,
tensor schema, shared task, and the complete training policy and settings, including
batch size, seed, and device. Restore revalidates actual records, tensor values,
optimizer structure, counters, and RNG states, then installs a fully restored fresh
backend only after all checks succeed. Missing or incompatible context is rejected.
Explicit offline restore into another run is supported when this context and local
data match; run IDs and filesystem paths are not part of the restore context. A
failed fixed-membership group still terminates and does not automatically resume.

## Synthetic experiment matrix

[Data-plan version 1](data_plan.py) uses four classes and eight FP32 features:

| Profile | Local distribution |
|---|---|
| `iid` | Balanced classes; 128 training examples per node |
| `label-skew-moderate` | Dominant class probability 0.7; each other class 0.1 |
| `label-skew-severe` | Only the node's dominant class is present |
| `quantity-skew` | Training counts 32, 64, 128, and 256 across each four-node group |
| `feature-skew` | Node-specific shifts/scales in nuisance features; class meanings unchanged |

Each node has 64 held-out examples from its local distribution. A separate balanced
512-example common evaluation set measures cross-distribution performance. Report
these evaluation scopes separately, including per-node and worst-node results.

The initial runner configuration uses seed 17, four nodes, a linear classifier,
eight NoLoCo rounds of 50 Adam steps, and matched initialization and peer schedules.
It compares identity and bitmap top-k 45%/dense-int8 Dromeus against an independent
NoLoCo control and local-only training. Predeclared experimental gates are common
mean accuracy at least 0.8, minimum node accuracy at least 0.6, compressed/identity
accuracy gap at most 0.1, and identity/reference outer-step parity at
`atol = rtol = 1e-6`. These gates belong to this synthetic experiment; they do not
replace M2's official acceptance criteria or establish general non-IID convergence.

The runner CLI is:

```bash
uv run python -m benchmarks.federated.runner \
  --transport in-memory --output-dir /tmp/dromeus-federated-in-memory

uv run python -m benchmarks.federated.runner \
  --transport axl --axl-binary /path/to/verified/axl-node \
  --output-dir /tmp/dromeus-federated-axl
```

Use a fresh output directory. The default includes all five profiles; select a
subset with `--profiles iid,label-skew-severe`. The local
[AXL harness](local_axl.py) launches independent AXL processes on loopback and
retains their logs and topology. An in-memory result exercises production runtime
logic; a local AXL result additionally exercises real AXL delivery. Neither measures
WAN behavior or the official GPU workload.

Retained outputs include `experiment.json`, `provenance.json`, source provenance,
`data/<profile>/data-plan.json` and synthetic NPZs, initialization, per-variant drafts,
node logs, run stores and analysis snapshots, control results, `results.json`, and
`report.md`. Read the generated report and failed gates before interpreting an
execution as a successful experiment.
